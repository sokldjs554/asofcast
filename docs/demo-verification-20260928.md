## 소스와 검증 범위

구현 PR: [#13](https://github.com/sokldjs554/asofcast/pull/13). 구현 커밋: `1aaddf10b9b19cc004cbef3d93e873f0e6936b76`.

- Python 3.12 로컬 단위·통합: **122개 통과**. Starlette/httpx 사용 중단 예정 경고 1개가 있었으며 실패는 없었다.
- 공개 데모와 동일한 생성 조건의 합성 모델 번들: **브라우저 37개 × 3회 통과**, 실패·오류·건너뜀 0개. 전송 경로는 Chromium DOM과 실제 FastAPI/PyTorch를 연결한 로컬 TestClient bridge이며 공개 HTTP 검사와 구분한다.
- 추가한 비교 회귀 시나리오 10개: 독립 분기 계산, 사후 평가 분리, 늦은 응답 폐기, 일부 실패·재시도, 마지막 대기 시점, 출처 있는 JSON, Commit 중·후 센서 유지, 기존 취득값 전달, 취득 후보 소진.
- 독립 코드 리뷰에서 발견한 센서 선택 불일치·대기 실패 문구·취득 상태 테스트 부족을 수정하고 재현 검사를 다시 통과했다.
- 실제 localhost HTTP로 캡처 스크립트를 실행해 짧은 녹화·이미지 10개·비교 JSON 생성 경로를 확인했다. 이것만으로 공개 서비스 검증을 주장하지 않는다.

[GitHub PR 검증 실행](https://github.com/sokldjs554/asofcast/actions/runs/36389021262)의 해당 7개 작업이 모두 통과했다. Python 3.11/3.13, ETTh1, ONNX Runtime, 공식 DLinear 대조, MLflow/DVC 및 합성·ETTh1 브라우저 반복 검증이다. 브라우저는 각 데이터 종류에서 37개 × 3회, 총 222개 실행이 통과했다. main 전용 Spark·클라우드 검사는 PR에서는 실행하지 않는다. 공개 배포와 미디어의 실행 근거는 아래에 기록한다.

## 공개 화면의 출처

기능 병합 커밋 `b0c952a034fb55d9b2f47fed0226b3bf9d83c80c`의 [main CI](https://github.com/sokldjs554/asofcast/actions/runs/36389658845) **9개 작업 모두 성공**. Spark/Parquet 51,894,720개 측정 셀 처리와 공개 `/health`·`/ready` 검사도 포함한다. Render 배포 `dep-dat12s8473hc738aie6g`가 `live`임을 확인했다.

[공개 촬영 실행](https://github.com/sokldjs554/asofcast/actions/runs/36389658868), 두 번째 시도에서 성공한 아티팩트 `10956501263`의 실제 화면을 보관했다. 첫 시도는 배포 완료를 기다리면서 현재 UI 버전을 찾지 못해 실패했다(HTTP 200). 배포 후 새 브라우저로 재시도하여 성공했다. 이어서 반복 `goto`가 이전 HTML 캐시를 재사용하는 동작을 재현했고, 앞으로 재시도할 때 문서를 `reload`로 재검증하도록 고쳤다. 재시도 진단 정보도 로그에 남긴다.

MP4는 공개 촬영본 31.64초에서 처음의 빈 화면·초기 로딩 3초만 제외한 **28.64초, 1440×1000 H.264**이다. 나머지는 원래 재생 속도를 유지한다. GIF는 같은 시연의 800px·4fps 미리보기다. [미디어 명세](assets/live-m2/media-manifest.json)에 변환 조건과 파일 해시를 기록했다. 이후 촬영은 첫 화면 준비 시점을 보고서에 기록해 앞부분을 자동으로 정리한다.

[캡처 보고서](assets/live-m2/capture-report.json)에는 서비스 URL, UI 버전, 촬영 시각, 모델 실행 ID, 데이터 종류, 실제 실행한 추천과 직접 취득한 센서, 고정 목표가 기록된다. [비교 JSON](assets/live-m2/comparison-example.json)은 화면의 저장 버튼으로 내려받은 원본이다. 이 예시는 사후 평가를 켠 상태이므로 정답·절대 오차를 포함한다.

영상은 서버 준비를 마친 뒤 **추천 실행 → 초기화 → 세 선택 비교 → 사후 오차 확인 → 결과 저장 → 센서 직접 취득**을 실제로 수행한다. 모바일·전문가 화면 캡처와 서버 준비 대기는 짧은 영상 밖에서 실행한다. 영상용 가짜 예측값이나 연출용 모델 추천을 주입하지 않는다.

## 재현

검증한 모델 번들이 있는 환경에서:

```bash
python scripts/check_browser.py --artifacts artifacts/demo --repeats 3 --out artifacts/browser-audit
python scripts/capture_live_demo.py --url https://asofcast.onrender.com --out docs/assets/live-m2
```

캡처에는 Chromium과 한글 글꼴이 필요하다. GitHub Actions의 [캡처 워크플로](../.github/workflows/capture-demo.yml)는 해당 환경을 준비하고 WebM을 MP4/GIF로 변환한다. 녹화 영상은 원래 시간 흐름을 유지한다.

## 남아 있는 한계

이번 변경은 전달력·비교 기능·상태 관리·증빙의 보완이며 모델 학습이나 정확도 개선이 아니다. ETTh1에서 학습형 취득의 MAE 개선 폭은 작고 일반적인 성능 우위는 입증되지 않았다. 공개 체험은 합성 데이터이며 실제 장비 제어, 영구 사용자 기록, 인증, 다중 사용자 부하 및 운영 SLA를 검증한 서비스가 아니다. 기존 실험의 상세 조건과 정정 내용은 [검증 수정 기록](verification-repair.md)을 따른다.

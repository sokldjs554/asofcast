# AsOfCast 모델 개선과 순차 행동 검증 · 2026-09-29

**판정: 예측기 개선은 일부 데이터에서 확인됐지만, 전체 행동 정책의 일반적인 우위는 입증하지 못했다. 사전에 정한 새 데이터 채택 기준은 실패했다.**

이번에는 데모 변경 없이 ① 개선 가능성 진단, ② 예측기·행동 선택기의 분리 개선, ③ 전체 WAIT/ACQUIRE/COMMIT 평가, ④ 미사용 데이터 최종 평가, ⑤ 사전 기준에 따른 판정과 재현 검증을 진행했다. 성능 기준을 통과하도록 결과를 고르거나 기준을 낮추지 않았다.

## 1. 먼저 확인한 개선 여지

기존 9월 28일 원시 결과를 그대로 사용했다. 정답을 알고 최선의 센서를 하나 고르는 사후 oracle과, 정답을 알고 대기 시점을 고르는 oracle을 각각 계산했다. 센서 비용은 저장된 행동별 비용에서 모든 센서에 대해 정확하게 복원했고 추정값을 넣지 않았다. 두 oracle을 결합한 순차 최적 정책은 아니다. 이 수치는 현재 관측으로 달성 가능한 이득을 보장하지 않는다.

| 데이터·조건 | 센서 하나를 최적으로 고를 때 손실 감소 | 대기 시점을 최적으로 고를 때 손실 감소 | 기존 MLP의 실제 손실 감소 |
|---|---:|---:|---:|
| ETTh1/mixed_1811 | 5.81% | 8.25% | -2.50% |
| ETTh1/mixed_811 | 5.28% | 8.07% | -2.18% |
| ETTh1/outage_1811 | 6.96% | 7.25% | -3.83% |
| ETTh2/mixed_1811 | 12.15% | 11.90% | 1.16% |
| ETTh2/mixed_811 | 11.42% | 11.36% | 0.25% |
| ETTh2/outage_1811 | 14.01% | 11.34% | 2.13% |

센서를 잘 고를 여지는 약 5~14%였지만, 기존 정책은 대부분 얻지 못했다. 다만 숨겨진 정답의 우연한 변동까지 활용하는 oracle과의 차이가 모두 학습 가능한 것은 아니다. 이를 행동 가치 추정의 개선 후보를 시험할 근거로 사용했다.

## 2. 무엇을 바꿨고 어떻게 분리했나

- **예측 후보:** 기존 보정 예측기를 유지하면서 최근 1·4·12·24시간의 변화·평균·변동성과 현재 도착 정보를 쓰는 작은 트리 잔차 보정기를 추가했다. MAE에 맞춘 절대오차 손실로 학습했다. 잎 수 7/15와 보정 비중 0/0.5/1 중 검증 구간에서 선택하며, 비중 0은 기존 예측기 유지다.
- **정책 후보:** 센서별 취득·다음 대기의 예상 오차 감소를 작은 트리로 학습했다. 센서를 이미 확보한 상태도 정책 학습에 포함했다. 현재 스냅샷만 보고 예상 이득에서 대기·수집 비용과 검증에서 선택한 여유값을 차감한다. 여전히 한 단계 이득을 추정하는 정책이며 장기 최적 정책은 아니다.
- **분리 비교:** 기존 조합, 예측기만 교체, 정책만 교체, 둘 다 교체, 추가 특징의 도착 정보 제거를 따로 평가했다. `value_features`는 추가 특징의 도착 정보 제거이며 기존 보정 예측기의 도착 정보까지 모두 제거한 실험은 아니다.
- **강한 단순 기준:** 즉시/30분/60분 대기 × 추가 수집 없음/목표 센서/가장 오래된 센서 × 기존/개선/추가 특징 제거 예측기의 27개 조합 중 검증에서 선택했다. 단순 기준도 개선 예측기를 쓸 수 있게 했다. 별도로 무작위 센서 취득과 DLinear도 보고했다. 무작위 기준은 같은 횟수·비용을 정확히 맞춘 비교라는 뜻이 아니다.

## 3. 고정한 조건과 판정 기준

프로토콜을 로컬 커밋 `2758d55`에 먼저 고정하고 새 데이터 실험을 실행했다. 같은 파일은 원격 커밋 `552655d69d5533bd4f3bfaa935f76d039eac097b`에 보존했다. 실행 코드는 `ce4240229c51be92b546b988981a82e1c36f682d`이며 같은 Git 트리는 원격 `6c3cc20ad9501860ea1fb33efadab2bfbce8b840`에 있다. 보고서의 파일별 SHA-256으로 실제 코드를 대조할 수 있다.

- 시간순 학습/정책 학습/검증/최종 평가 비율 55/20/10/15%, 48시간 관측으로 6시간 뒤 고정 목표 예측, 평가 시작점 간격 4시간.
- 판단 시점 0/30/60분, 마지막 판단까지 최대 1시간. 이미 수집한 기준 시각 값은 대기 뒤에도 유지하고 같은 센서를 중복 수집하지 않는다. 한 번의 취득은 기준 시각 값 하나만 공개한다.
- 학습 시드 42/43/44, 지연 조건 mixed-2811/mixed-3811/outage-2811. 모든 방법은 같은 목표·정보 접근 규칙·센서 비용·마감 시간을 사용한다.
- 손실 = 학습 구간 척도로 표준화한 절대오차 + 0.03 × 총 상대 수집 비용 + 0.02 × 대기시간/3600. 서로 다른 데이터의 원단위 오차는 합쳐 비교하지 않는다.
- **새 데이터의 6개 조건 모두에서** 기존 순차 정책과 검증 선택 단순 기준 각각보다 손실 1% 이상 감소, 개선량 95% 구간 하한 > 0, 세 학습 시드 모두 개선, 각 시드 MAE 악화 최대 1%를 요구했다.
- 동일 시작점의 시드별 개선량을 먼저 평균한 뒤 42개 시작점(1주) 단위 circular moving-block bootstrap 2,000회. 6개 시작점 블록 민감도와 최종 구간의 4개 시간대별 개선량도 원시 보고서에 남겼다. 구간은 관측한 데이터와 세 시드에 조건부다.

## 4. 데이터 범위

ETTh1·ETTh2는 이미 결과를 확인한 개발 데이터다. 이번에 새로 최종 평가한 Appliances와 Tetouan은 각각 건물과 도시 전력 데이터다. 장비·지역을 넓혔지만 에너지 분야 안의 평가이며 모든 산업으로 일반화할 근거는 아니다. 각 데이터셋에서 별도로 학습했으므로 zero-shot 전이가 아니다.

| 데이터 | 최종 평가 시작점 / 시드·조건 | 역할 |
|---|---:|---|
| ETTh1 | 640 | 기존 개발 데이터 |
| ETTh2 | 640 | 기존 개발 데이터 |
| Appliances | 111 | 새 최종 평가 |
| Tetouan | 315 | 새 최종 평가 |

UCI 원본의 10분 데이터를 (이전 1시간, 현재 시각]의 6개 값 평균으로 집계하고 현재 시각에 붙였다. 불완전한 양 끝 구간만 제거하고 내부 누락은 오류 처리했다. 미래 방향 보간은 하지 않았다. Appliances는 미리 정한 실내 온습도 6개와 Appliances를 사용했고, Tetouan은 8개 수치 열을 모두 사용했다. 값이 좋은 열·기간을 보고 사후 선택하지 않았다.

Appliances는 약 4.5개월로 짧아서 최종 구간의 주 단위 블록 수가 적다. 실제 도착 로그와 실제 수집 비용은 없으며 취득 지연은 0인 시뮬레이션이다. 따라서 운영 현장의 절감액이나 응답시간 개선으로 읽을 수 없다.

ETTh2의 일부 행동 개선은 기존에 노출된 개발 데이터 결과다. 이를 새 데이터 확인 실패를 대신하는 근거로 사용하지 않았다. 모든 36개 설정 × 15개 방법의 성적, 실제 행동열, 시작점별 손실은 원시 파일에 보존했다.

## 7. 재현과 검증

처음부터 독립 재학습한 두 실행에서 **4,452개 배열, 72쌍의 체크포인트와 576개 텐서, 모든 선택·성적·구간·판정이 정확하게 일치**했다. [재현 기록](assets/research-diagnosis/reproducibility.json)에 비교 결과를 보존했다. 별도 코드 리뷰에서 연구 테스트 12개와 기존 서비스의 72개 상태에 대한 행동 선택 일치가 확인됐다. 전체 테스트 152개를 반복 실행했으며 이 테스트 성공은 성능 기준 통과와 별개다.

```bash
python -m pip install "torch==2.10.0" --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[dev,research]" "numpy==2.3.5" "scikit-learn==1.8.0"
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 PYTHONPATH=src python scripts/evaluate_research_diagnosis.py --out artifacts/research/run1
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 PYTHONPATH=src python scripts/evaluate_research_diagnosis.py --models artifacts/research/models-repeat --out artifacts/research/run2
python -m pytest -q
```

실행 환경: Python 3.12.14, PyTorch 2.10.0 CPU, NumPy 2.3.5, scikit-learn 1.8.0, 스레드 2개. 첫 명령의 모델 저장소 기본값과 두 번째 명령의 별도 모델 저장소를 사용해 처음부터 다시 학습한다. 새 결과 디렉터리는 기존 결과를 덮어쓰지 않는다. 원본 다운로드에 실패하면 합성 데이터로 대체하지 않는다.

현재 실험에서는 기존 번들 학습 함수가 보조적인 기존 방식의 테스트 보고서도 자동 생성한다. 후보군과 프로토콜을 그 전에 고정했고, 새 후보 학습·선택 함수는 그 테스트 성적을 읽지 않는다. 최종 테스트 값을 크게 바꿔도 선택과 검증 예측·행동열이 변하지 않는 회귀 테스트를 포함했다. 이번 평가 뒤 두 새 데이터의 테스트도 노출된 것으로 취급하므로 후속 튜닝의 새 확인 근거로 재사용할 수 없다.

공개 데모의 예측 모델은 교체하지 않았다. 앞으로의 연구 과제는 더 좋은 숫자가 나올 때까지 테스트를 반복하는 것이 아니라, 현재 상태만으로 정보의 가치를 예측하기 어려운 이유를 분석하고 실제 도착 기록·비용을 갖춘 새로운 확인 데이터에서 검증하는 것이다.

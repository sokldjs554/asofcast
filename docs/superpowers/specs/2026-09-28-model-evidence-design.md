# 모델 성능 근거 보완 설계

목표는 UI·실행 성공과 모델의 유용성을 구분하고, 센서 추가 취득 정책의 효과를 비용까지 포함해 검증하는 것이다. 사용자 지적에 따라 프로젝트 전체 완료 주장을 철회한다. 성능 향상 자체를 약속하거나 좋은 결과가 나올 때까지 평가 설정을 바꾸지 않는다.

## 고정 실험

- 기존 ETTh1은 이미 결과를 본 데이터다. ETTh2는 이번 비교의 추가 데이터셋이며, 최종 평가 전에 후보·선택 절차·기준을 고정한다. 두 데이터 모두 같은 ETT 계열이므로 산업 전반의 일반화 근거는 아니다.
- 원본 Git blob을 검증한다. ETTh1 `a52c4925778c07c1ef1a2cf6fd01594919717d9e`, ETTh2 `6e3760778598fdee5208213d3fce122637307eec`.
- 기존 55/20/10/15% 시간 분할, lookback=48, horizon=6, stride=4를 유지한다. 학습 정규화·도착한 라벨 필터도 유지한다.
- 학습 seed=42,43,44. 학습 도착 seed=811. 평가 조건은 mixed/811, mixed/1811, outage/1811. 각 데이터셋은 자기 학습 구간으로 학습하므로 데이터셋 간 zero-shot 전이는 아니다.
- 후보는 기존 MLP와 센서별 ridge 이득 회귀(alpha=1,10,100,1000)다. ridge는 기존 causal acquisition_features만 사용하며 policy 구간에서만 학습한다. alpha는 validation 구간의 비용 포함 손실로 선택한다.
- 단순 기준: 추가 취득 없음, 타깃 센서 우선, 가장 오래된 미도착 센서 우선, policy 구간 센서별 평균 이득. validation에서 가장 좋은 단순 기준도 따로 고정한다.
- 현재 MLP 및 ridge의 취득 여부와 같은 시점에서 센서만 균등 무작위로 정하는 기준의 기대 손실을 정확히 계산한다. 취득률은 같지만 센서별 상대 비용은 다를 수 있으므로 비용도 함께 보고한다.
- 주 지표는 표준화 절대 오차 + 0.03 × 상대 취득 비용. 원 단위 MAE, 취득률, 비용도 모두 보고한다. 비용 가중치를 평가 결과에 맞춰 바꾸지 않는다.
- 같은 target·origin의 짝지은 차이를 사용한다. seed 평균 시계열에 circular moving-block bootstrap 2,000회, block=42 origins(168시간), 95% 구간을 계산한다. block=6은 민감도 참고용이다. 구간은 관측한 세 학습 seed에 조건부이며 전체 데이터 모집단에 대한 보장이 아니다.
- 채택 기준: 2 datasets × 3 conditions 각각에서 ridge가 현재 MLP와 validation-selected simple 모두에 대해 주 지표 개선 구간 하한 > 0, 세 seed 각각 개선 > 0, 각 seed MAE가 단순 기준 대비 1% 이상 악화하지 않을 것. 하나라도 실패하면 공개 모델 미교체. 보조 지표가 좋아도 이 기준을 우회하지 않는다.
- 예측기 자체(DLinear/보정 모델/최근 값 유지)의 성능과 기존 대기 정책도 별도 표로 보고한다. 전체 WAIT/ACQUIRE/COMMIT 순차 정책의 우위를 one-shot 취득 실험으로 주장하지 않는다.

## 구현 경계

새 연구 평가 모듈과 실행 스크립트만 추가한다. 현재 공개 UI·API·번들 형식은 바꾸지 않는다. 실제 실험 결과·프로토콜 해시·설정·샘플별 손실·출처·실패 판정을 보관한다. 기존 테스트와 신규 계산 검증, 반복 실행 일치, 독립 코드 검토를 거친다.

## 중단 기준

고정된 전체 실험을 두 번 실행해 결과가 일치하면 보고한다. ETTh2 최종 결과를 본 뒤 후보나 hyperparameter를 추가하지 않는다. 성능 게이트 실패는 실패로 문서화하고 완료 범위를 평가 도구/실험 실행과 모델 우위 확보로 구분한다.

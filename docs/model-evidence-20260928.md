# 모델 성능 검증 · 2026-09-28

**모델의 일반적인 성능 우위는 확보하지 못했다.** 데모·API·배포의 작동 완료와 모델 개선 목표 달성을 구분한다. 이번에는 단순히 검증 부족이라고 남겨 두지 않고 실제 추가 데이터, 초기값, 지연 조건과 개선 후보를 고정해 실행했다. 개선 후보는 채택 기준에 실패했으므로 공개 모델을 교체하지 않았다.

## 어떤 빈틈을 보완했나

기존 대표 ETTh1 결과는 한 초기값에서 즉시 확정 MAE 1.10460, 학습형 취득 1.10366이었다. 약 0.086%의 작은 차이만으로 일반적인 개선이나 취득 비용을 감수할 가치를 주장할 수 없었다. 기존 CI도 정상 학습·API·무결성·평가 실행을 검증할 뿐, 정책이 기준 방법보다 우수함을 보장하지 않았다.

- 고정된 ETTh1·ETTh2 원본을 각각 시간순 55/20/10/15% 구간으로 분할했다. ETTh1의 과거 test 결과는 이미 알려져 있었다. ETTh2는 이번 평가에서 추가한 같은 ETT 계열 데이터이며 두 데이터셋에 각각 모델을 학습했다. Zero-shot 전이 실험이 아니다.
- seed 42/43/44, 도착 조건 mixed/811, mixed/1811, outage/1811로 총 18개 설정을 평가했다. 학습 도착 seed는 811로 고정했다. 각 설정의 최종 평가는 640개 origin이다.
- 기존 MLP와 센서별 ridge 이득 회귀를 비교했다. ridge 1/10/100/1000 후보는 policy 구간에서만 학습하고 validation 구간에서만 선택했다.
- 추가 취득 없음, 타깃 센서 우선, 가장 오래된 센서 우선, policy 구간 센서별 평균 이득을 단순 기준으로 사용했다. validation에서 가장 좋은 단순 기준은 모든 학습 seed에서 추가 취득 없음이었다.
- MLP/ridge 각각의 취득 시점·취득률을 그대로 둔 균등 무작위 센서 선택의 **기대 손실**도 계산했다. 센서별 비용은 다르므로 무작위 기준의 기대 비용을 따로 반영했다.

[고정 프로토콜](../configs/model_evidence_20260928.json)과 [사전 설계](superpowers/specs/2026-09-28-model-evidence-design.md)를 개선 후보의 ETTh2 결과를 보기 전에 기록했다. 결과를 본 뒤 후보·비용 가중치·지연 조건을 바꾸지 않았다. 이후에는 중복 seed가 여러 번의 독립 학습처럼 집계되지 않도록 입력 검증만 보강했다.

## 비용을 포함한 취득 정책 결과

주 지표 = **표준화 절대 오차 + 0.03 × 상대 취득 비용**. 낮을수록 좋다. 아래는 같은 origin에서 seed 3개를 평균한 값이다. 데이터셋 사이에는 표준화 기준이 다르므로 평균을 합쳐 하나의 성능 점수로 만들지 않았다.

| 데이터 / 도착 조건 | 바로 확정 | 기존 MLP | 새 ridge 후보 | 확정 대비 ridge 개선량의 95% 구간 |
|---|---:|---:|---:|---:|
| ETTh1 / mixed 811 | 0.125787 | 0.128531 | 0.126021 | [-0.000764, 0.000275] |
| ETTh1 / mixed 1811 | 0.127280 | 0.130468 | 0.127761 | [-0.000947, -0.000093] |
| ETTh1 / outage 1811 | 0.128320 | 0.133240 | 0.129544 | [-0.001950, -0.000446] |
| ETTh2 / mixed 811 | 0.219327 | 0.218770 | 0.219153 | [-0.003083, 0.003638] |
| ETTh2 / mixed 1811 | 0.222432 | 0.219845 | 0.219140 | [-0.000250, 0.007258] |
| ETTh2 / outage 1811 | 0.226419 | 0.221591 | 0.220813 | [0.001361, 0.010367] |

개선량은 **기준 손실 − 후보 손실**이다. 양수면 후보가 유리하다. ETTh1에서는 ridge가 기존 MLP의 비용 포함 손실을 줄였지만 즉시 확정 기준을 이기지 못했다. ETTh2에서는 유리한 평균값이 나온 조건도 있지만 기존 MLP와의 비교, 모든 seed의 개선, 전체 조건의 구간 기준을 모두 만족하지 못했다.

채택 조건은 2 datasets × 3 conditions **각각**에서 (1) 기존 MLP와 validation-selected simple 대비 개선 구간 하한 > 0, (2) 세 seed 각각 개선 > 0, (3) 단순 기준 대비 MAE 악화가 seed별 1% 이내인 것이다. 결과는 `promotion_gate.passed=false`다. 보조 결과가 좋다는 이유로 이 기준을 바꾸지 않았다.

구간은 3개 seed의 동일 origin 개선량을 먼저 평균한 뒤 시간 순서에 따라 circular block bootstrap 2,000회를 시행했다. block은 42 origins, 즉 168시간이다. 6 origins 구간도 민감도 참고로 원본 보고서에 남겼다. 학습 seed를 독립된 관측 시계열처럼 3배로 부풀리지 않았다. 이는 관측한 세 학습 seed와 해당 데이터에 조건부인 구간 추정이며 산업 전체에 대한 보장이 아니다.

## 예측기 자체의 결과

센서 취득 판단과 그 아래의 예측기는 구분해야 한다. 다음은 아무것도 추가 취득하지 않은 상태의 원 단위 MAE다.

| 데이터 / 도착 조건 | DLinear | 현재 보정 예측기 | DLinear 대비 MAE 감소율 |
|---|---:|---:|---:|
| ETTh1 / mixed 811 | 1.1254 | 1.1083 | 1.52% |
| ETTh1 / mixed 1811 | 1.1465 | 1.1214 | 2.19% |
| ETTh1 / outage 1811 | 1.1546 | 1.1306 | 2.08% |
| ETTh2 / mixed 811 | 2.6459 | 2.6463 | -0.01% |
| ETTh2 / mixed 1811 | 2.6746 | 2.6837 | -0.34% |
| ETTh2 / outage 1811 | 2.7181 | 2.7318 | -0.51% |

ETTh1에서 보정의 이득이 있었지만 ETTh2에서는 재현되지 않았다. 최근 값 유지, value-only, arrival MLP와의 비교도 원본 보고서에 포함했다. 기존 대기 정책, validation-selected fixed wait, 동일 대기 분포 무작위 비교 역시 별도 기록했다. 이 보조 비교를 전체 WAIT/ACQUIRE/COMMIT 순차 정책의 우위로 해석하지 않는다.

## 실행 근거와 재현

Python 3.12.14, PyTorch 2.10.0+cpu, NumPy 2.3.5, CPU 2 threads에서 실행했다. 새로운 계산·누출 방지 검증을 포함한 단위·통합 140개가 통과했다. 테스트 구간의 측정값을 크게 바꿔도 ridge 학습 계수·검증 구간 선택이 변하지 않는지 실제 모델로 확인했다. 독립 코드 리뷰에서도 고정 프로토콜의 수학·시간 누출 관련 차단 문제는 발견되지 않았다.

최초 전체 실행 후 반복 seed의 누락/중복 입력 검증을 보강했다. 후보·학습 설정은 유지하고 최종 코드로 두 번 더 실행했다. 두 번의 18개 설정에서 모든 원시 배열, 학습 체크포인트 텐서, 검증 구간 선택과 채택 실패 판정이 일치했다. 보강 전 첫 실행의 수치와도 같았다. 이는 같은 CPU 환경의 재현 확인이며 외부 산업 일반화 증거가 아니다.

각 실행은 체크섬이 고정된 ETTh1/ETTh2를 받고, 별도 모델 6개를 학습하며, 모든 지연 조건을 평가한다. 이미 존재하는 출력 디렉터리는 덮어쓰지 않는다. 프로토콜·학습 설정·실행 코드 해시와 per-origin 손실을 함께 보관한다. 학습 번들 전체는 실행 디렉터리에 생성되며 공개 서비스 번들을 대체하지 않는다.

## 정확히 남아 있는 것

평가 도구와 연구 데모의 구현은 모델 우위 확보와 다른 완료 기준이다. 현재 남은 핵심은 **데이터셋이 바뀌어도 유지되는 보정 효과**, **단순 기준보다 나은 비용 포함 취득 판단**, 그리고 **전체 순차 정책의 평가**다. 이를 확보하기 전에는 프로젝트 전체의 모델 개선 목표를 완료했다고 보고하지 않는다.

실제 산업 도착 로그·실측 취득 비용·외부 산업 데이터, 전체 순차 정책의 효과는 이번 실험으로 검증하지 않았다. ETTh2 평가 결과를 본 뒤 같은 test에 맞춰 다시 후보를 조정하지 않으며, 후속 모델 선택에는 별도 검증 설계가 필요하다.

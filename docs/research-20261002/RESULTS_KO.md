# AsOfCast 후속 연구 결과 · 2026년 10월 2일

> 이 문서는 2026-10-02 보존 연구 묶음의 보고서입니다. 2026-10-04 저장소 통합 범위와 현재 재현 방법은 [통합 기록](INTEGRATION.md)을 먼저 확인하세요. 당시 경로·환경·공개 상태는 역사적 기록이며 현재 배포 상태와 구분합니다.

## 최종 판정

**전체 성능 목표 미달성. 공개 모델 승격 없음.** 이번 기록은 새 연구 후보의 구현·실측 평가·반복 재학습·회귀 검증을 수행한 결과이며, AsOfCast의 일반적인 성능 우위를 달성했다는 보고서가 아니다.

새 실측 자료 2종 × 학습 시드 3개 × 도착 조건 3개, 총 18개 설정을 평가했다. 시드별 결과를 묶은 6개 자료·조건 중 사전 지정 수치 기준을 모두 충족한 조건은 **Taylor/mixed_2811 한 개**였다. 모든 조건을 통과해야 하는 전체 판정은 실패했다. 이미 노출된 ETTh1의 9개 개발 설정은 별도이며 새 독립 자료로 세지 않았다. 이전 Jena2020/GasCO의 0/6 실패를 덮어쓰지 않았고, 서로 다른 자료의 결과를 0→1 개선이라고 부르지 않았다.

## 1. 이번에 구현한 것

기존 방식은 추가 관측 전후의 실제 절대오차 차이를 회귀했다. 새 후보에서는 학습 자료로 선형 Gaussian 시계열 모형을 만들고, 현재 도착한 정보로 추정한 예측 불확실성이 센서 취득이나 대기 후 얼마나 줄어드는지 계산했다. 여러 센서가 함께 있을 때만 도움이 되는 경우를 놓치지 않도록 가능한 센서 부분집합을 비교했다. 대기는 학습 구간에서 추정한 도착 분포와 8개 고정 난수 표본으로 계산했다.

구현은 `src/asofcast/posterior_risk.py`, `src/asofcast/posterior_policy.py`에 있다. 기존 `rollout`의 고정 목표·합법 행동·비용 계산을 그대로 사용했다. 측정 시점이 기준 시점 이후인 값, 아직 도착하지 않은 값, 최종 정답은 정책 입력으로 제공하지 않았다. 취득한 기준 시점 값은 대기 뒤에도 유지했다.

처음에는 Gaussian 예측기까지 바꾸었으나, ETTh1 개발 결과에서 같은 예측기의 단순 방법보다 좋아지는 경우가 있어도 기존 강한 예측기에 못 미쳤다. 이 실패를 보존한 뒤, **기존 예측기는 유지하고 불확실성 신호만 행동 선택에 쓰는 후보**를 함께 평가하도록 새 자료 평가 전 후보군을 고정했다. 이는 원래 예측기의 정확한 확률적 사후분포가 아니라 **위험을 추정하는 대용 신호**다. Gaussian 가정 안의 계산이 맞는다는 사실과 실제 시계열에서 판단이 좋아진다는 사실은 다르다.

예측기만 변경, 정책만 변경, 둘 다 변경, 원래 방법, 강한 단순 방법 및 단순 방법 유지까지 총 9개 평가 방법을 기록했다. 단순 기준에는 이미 목표 센서가 도착했으면 불필요하게 기다리지 않는 상태 인지 방법도 추가했다. 단순 기준을 약화시켜 성공을 만들지 않았다.

## 2. 자료와 사전 고정

| 자료 | 측정값과 크기 | 역할과 해석 범위 |
|---|---|---|
| ETTh1 | 기존 변압기 시계열 | 이미 노출된 개발 자료. 이 결과로 새 자료 우위를 선언하지 않았다. |
| Taylor | 전력 수요 4,032개, 30분 간격, MW | 이번 연구에서 처음 최종 평가한 자료. 전체 12주 순서를 사용했다. |
| MSFT | 7,983개 거래 관측의 Open/High/Low/Close/Volume | 다른 분야의 새 확인 자료. 투자 성과나 체결 가격 예측의 우위를 검증한 것이 아니다. |

Taylor 원 제공자는 2000-06-05~2000-08-27의 자료로 설명한다. 번들에 원래 시계 정렬 정보가 없어 계산용 `2000-01-01` 기준점을 명시적으로 사용했다. 원래 관측 시각을 복원했다는 뜻은 아니다. MSFT의 원 날짜 1986-03-13~2017-11-10은 별도 대응표로 보존했고, 계산의 한 칸은 **거래 관측 한 개**다. 주말·휴일까지 실제 도착 지연으로 해석할 수 없다.

측정값은 실제 자료지만 **도착 기록, 센서 정보 비용과 취득 지연은 실측 운영 자료가 아니다.** 도착·비용을 시뮬레이션하고 취득 지연을 0으로 두었다. 실제 설비의 비용 절감이나 기업 운영 효과를 입증하지 않았다. 자료는 모델 점수를 보기 전에 로컬 번들의 가용성·길이·분야 차이로 골랐고 전체 기간을 사용했다. 원본 숫자 셀과 준비한 CSV의 해시를 보존했다.

동학 학습은 train에서, 위험 보정은 policy에서, 후보 선택은 validation에서 수행했다. 최종 평가 점수는 후보 선택에 쓰지 않았다. 시간순 분할 55/20/10/15%, 관측 48칸, 미래 목표 6칸, 시작점 간격 4칸을 유지했다. 자료마다 마감은 한 관측 간격이고 판단 시점은 0·절반·마감이다.

후보·조건·비용·판정 기준은 **새 자료의 첫 모델 성적을 보기 전에 로컬 커밋으로 고정**했다. 공개 원격 사전등록을 했다는 뜻은 아니다.

- 원격 원본 main: `80f2124c64e4ce7f4e4cd44d04a4570c65e3e86c`
- 복구에 사용한 원격 소스 아카이브: `5a239b2ee738062e946ae86e7a71d654179b7040`
- 아카이브 Git 트리: `47a4f2003c187b47d143e5379984eda121d7b3cd` — 145개 추적 파일의 blob 해시 일치
- 새 자료 평가 전 로컬 고정 커밋: `7ce1200a450a4eaa9fab750ec7e8a11b8bc2d463`
- 고정 프로토콜 SHA-256: `3084c79e56caf5cbe69ee7bcb5a9689f9ce5eb159c338621e75eae5f10331ef9`

로컬 저장소는 검증한 소스 아카이브를 가져와 초기화했으므로 로컬 커밋은 원격 저장소의 같은 해시를 뜻하지 않는다. 첫 평가 뒤에는 출력 덮어쓰기 방지, 자료 직렬화의 줄바꿈 고정, 이동 가능한 실행 명령과 패키징을 보완했다. 수치 모형·비용·선택 기준은 바꾸지 않았고, 최종 실행기로 전 과정을 다시 학습해 원시 수치가 정확히 같은지 확인했다.

## 3. 변경하지 않은 완료 기준

평가 손실은 다음과 같다.

`학습 척도로 표준화한 절대오차 + 0.03 × 총 상대 취득 비용 + 0.02 × 대기시간/마감`

각 사전 지정 자료·도착 조건에서 원래 정책과 강한 단순 기준 **각각** 대비 평균 손실 1% 이상 감소, 개선량의 paired-block 95% 구간 하한 양수, 세 학습 시드 모두 양수 개선, 각 시드의 원단위 MAE 악화 최대 1%를 요구했다. 여섯 조건 전부가 통과해야 전체 성공이다. 시드는 42/43/44, 조건은 mixed_2811/mixed_3811/outage_2811이다.

## 4. 새로운 자료의 전체 결과

개선율은 양수일 때 손실 감소다. 아래 구간은 백분율이 아니라 **강한 단순 기준 손실 − 후보 손실**의 표준화 손실 단위다. 각 개선율은 세 학습 시드의 평균 결과다.

| 자료 / 조건 | 원래 정책 대비 개선 | 강한 단순 기준 대비 개선 | 단순 기준 대비 95% 구간 | 단순 기준보다 개선된 시드 | 해당 조건 판정 |
|---|---:|---:|---|---:|---|
| Taylor/mixed_2811 | +34.03% | +5.82% | [0.002513, 0.017272] | 3/3 | 수치 기준 통과 |
| Taylor/mixed_3811 | +33.98% | +0.50% | [-0.007815, 0.013030] | 3/3 | 미달 |
| Taylor/outage_2811 | +29.01% | +5.60% | [-0.007916, 0.033780] | 3/3 | 미달 |
| MSFT/mixed_2811 | +7.85% | +0.00% | [0.000000, 0.000000] | 0/3 | 미달 |
| MSFT/mixed_3811 | +6.45% | +0.00% | [0.000000, 0.000000] | 0/3 | 미달 |
| MSFT/outage_2811 | +6.34% | +0.00% | [0.000000, 0.000000] | 0/3 | 미달 |

**Taylor/mixed_2811의 제한된 성과:** 강한 단순 기준 대비 손실이 약 5.82% 낮았으며 사전 지정 주 판정 기준은 통과했다. 그러나 보조 민감도 분석에서 블록 길이를 42개 시작점에서 6개로 바꾸면 구간이 0을 포함했다. 이 한 조건을 시간적 의존성에 관계없이 안정적인 우위가 입증된 것으로 표현하지 않는다.

**Taylor의 나머지 두 조건:** mixed_3811은 평균 개선이 1%에 못 미쳤고 주 구간도 0을 포함했다. outage_2811은 평균 개선이 약 5.60%였지만 주 구간이 0을 포함해 실패했다. 이 두 조건에서 평균이 양수라는 이유로 성공 처리하지 않았다.

**MSFT:** validation 선택이 강한 단순 방법을 그대로 유지했다. 단순 기준 대비 개선은 세 조건 모두 정확히 0이다. 원래 정책보다 비용 포함 평균 손실이 낮아져도 강한 단순 기준을 이긴 결과가 아니며, 일부 시드의 MAE 제한도 통과하지 못했다.

Taylor 최종 평가의 공유 시작점은 조건당 138개, MSFT는 287개다. 42개 시작점 블록으로 약 3.3개·6.8개 블록에 해당하므로 시계열별 불확실성 평가의 한계가 있다. 세 학습 시드의 같은 목표 시점은 독립 표본 세 개로 부풀리지 않았다. 신뢰구간은 관측된 시계열과 해당 시드에 조건부이며 다른 장소·기업 전체를 대표하지 않는다.

원시 예측, 행동열, 비용, 정답, 목표 시각, 원단위 오차, 후보 선택 이력과 모든 비교는 `artifacts/portable-final-suite/` 아래에 있다. `confirmation/aggregate.json`의 `general_goal_achieved`와 `gate.passed`는 모두 `false`다.

## 6. 실행 방법

압축을 푼 프로젝트 루트에서 실행한다. 처음 의존성을 설치할 때는 패키지 저장소 접속이 필요하다. 데이터 준비 단계는 설치된 pmdarima 번들의 원래 실측 자료를 읽으며 다운로드 실패를 가짜 자료로 대체하지 않는다.

```sh
python -m pip install '.[dev,research,browser]'
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 python -m pytest -q
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  python scripts/run_posterior_confirmation.py --out artifacts/my-confirmation-run
```

출력 경로는 새 경로여야 한다. 위 마지막 명령은 기본 번들 9개를 처음부터 학습하고, 후보 선택·평가·전체 판정까지 수행한다. 기존 연구 증거와 공개 모델을 덮어쓰지 않는다. 배포 동작은 포함하지 않는다. 원래 ETTh1 CSV는 제공한 프로젝트 묶음의 `data/raw/ETTh1.csv`를 사용한다.

기존 UI 회귀 검사는 다음과 같이 실행한다. Chromium 경로는 설치 위치에 맞추어야 한다.

```sh
python scripts/check_browser.py --browser /usr/bin/chromium \
  --artifacts artifacts/ett-m1 --repeats 3 --out artifacts/my-browser-check
```

`evidence`의 보존 스크립트 중 일부는 당시 작업 경로를 그대로 포함한 실행 증거다. 이동 가능한 연구 실행 진입점은 `scripts/run_posterior_confirmation.py`다. 라이브러리 설치만 검증한 것과 모든 의존성을 빈 OS에 새로 설치한 검증은 다르다. Windows/macOS와 Docker 환경의 새 검증을 했다고 주장하지 않는다.

## 7. 공개 상태와 남은 경계

이번 작업에서 원격 main, 공개 예측 모델, Render 서비스는 변경하지 않았다. 새 연구 모듈을 공개 API에 연결하거나 자동 승격하지 않았다. 최신 원격 CI·공개 URL의 가동 상태를 이 로컬 결과로 대체하지 않는다. Docker 및 Ruff 실행은 이 환경에서 수행하지 않았다. 이 항목들을 통과했다고 기록하지 않는다.

남은 핵심은 단순 방법보다 비용 포함 손실을 **모든 사전 지정 독립 조건에서 안정적으로 줄이는 것**이다. 새 후보가 그 목표를 이미 달성했다고 하거나, 추가 반복만 하면 반드시 달성한다고 단정하지 않는다. 이번에 사용한 Taylor/MSFT의 최종 구간도 이제 결과가 노출되었으므로 향후 변경한 정책을 같은 구간에 다시 평가해 새로운 독립 확인이라고 부를 수 없다.

## 8. 제공 묶음의 구성

소스 전체, 테스트, 실행기, 고정 프로토콜, 세 실행의 원시 평가 배열·선택·요약, 별도 감사 코드·결과, 브라우저 캡처와 로그, 원래 ETTh1 데모 번들, 원래 ETTh1 CSV, 검증된 wheel, 로컬 Git 이력과 변경 patch를 제공한다. 원시 평가 배열에는 평가 시점의 정답과 예측·행동 결과가 포함되어 있다.

Taylor/MSFT의 전체 새 원자료와 아홉 개씩의 기본 재학습 번들은 압축 묶음에 중복 배포하지 않는다. 해당 자료는 설치된 pmdarima 번들에서 정확한 해시로 다시 준비되며, `run_posterior_confirmation.py`가 새 출력 폴더에 모든 기본 모형 번들을 재생성한다. `reference-fit`에는 비교에 사용한 Gaussian 모형과 도착 분포 배열을 보존했다. 기본 신경망 텐서의 동일성 검사는 당시 전체 번들로 실행했고 검사 결과를 남겼다. 포함된 원래 데모 번들은 바로 로드 가능하다.

이 묶음을 새 GitHub 저장소나 웹에 자동 업로드하지 않았다. Git 이력은 소스 아카이브에서 시작한 로컬 연구 이력이고 원격 저장소의 전체 과거 이력이 아니다. `SHA256SUMS.txt`는 제공 파일의 무결성 확인용이며 성능 성공을 뜻하지 않는다.
